The Engineering Evolution of Universally Unique Identifiers (UUIDs)

A Universally Unique Identifier (UUID), also termed a Globally Unique Identifier (GUID), is a 128-bit label used to uniquely identify records, entities, and transactions across distributed systems without requiring a central coordinating authority. First formalized in 2005 under IETF RFC 4122, the UUID specification underwent its most significant modernization in 2024 with the publication of IETF RFC 9562, introducing time-ordered UUIDv7.

UUIDv4: Pure Pseudo-Random Generation

UUID version 4 is the most ubiquitous UUID format in computing. It comprises 128 bits structured as 32 hexadecimal characters partitioned into five groups separated by hyphens (8-4-4-4-12): 

xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx
              ^    ^
              |    +-- Variant bits (10xx binary = 8, 9, a, or b)
              +------- Version 4 identifier (0100 binary)

In a valid UUIDv4, 6 bits are permanently reserved for version (4) and variant (RFC 4122). The remaining 122 bits are generated from cryptographically secure pseudo-random entropy. The total number of distinct UUIDv4 values is $2^{122} \approx 5.3 \times 10^{36}$. The probability of generating a duplicate collision is so infinitesimal that even generating one billion UUIDs per second for a century yields an essentially zero chance of collision.

The Hidden Flaw of UUIDv4 in Databases (B-Tree Fragmentation)

While UUIDv4 is excellent for distributed generation, using it as a database primary key (in PostgreSQL, MySQL InnoDB, or SQLite) creates severe architectural performance degradation at scale:

Relational databases index primary keys using B-Tree data structures. Because UUIDv4 values are completely random, new inserts arrive with no sequential order. Each insert lands in an arbitrary branch of the B-Tree index. As the database grows beyond RAM cache, this random distribution causes continuous disk page swapping, severe page splits, and B-Tree fragmentation, causing write throughput to plunge by up to 80%.

UUIDv7: The Modern Database-Optimized Standard (RFC 9562)

To permanently solve the B-Tree fragmentation problem while retaining decentralized generation, the IETF developed UUIDv7:

  • First 48 bits: Unix timestamp in milliseconds since the epoch. This guarantees that newly generated UUIDs sort lexicographically in natural chronological order.
  • Next 4 bits: Version flag set to 7 (binary 0111).
  • Next 12 bits: Sub-millisecond sequence counter or random entropy.
  • Next 2 bits: RFC 4122 variant bits (binary 10).
  • Remaining 62 bits: Cryptographically secure random entropy.

Because UUIDv7 IDs are strictly monotonic over time, database inserts always append to the right edge of the B-Tree index, eliminating random page splits and preserving high write throughput while maintaining absolute collision resistance across distributed nodes.
