Comprehensive Guide to URL Encoding and URI Specification

Uniform Resource Identifiers (URIs) and Uniform Resource Locators (URLs) are the structural backbone of the World Wide Web. Standardized under IETF RFC 3986, the URI syntax defines how data is formatted and addressed across network boundaries.

What is Percent-Encoding and Why Is It Necessary?

URLs are strictly restricted to a finite subset of 7-bit US-ASCII characters. Furthermore, within this ASCII character set, characters are partitioned into two strict categories:

  • Unreserved Characters (Never Encoded): A–Z, a–z, 0–9, hyphen (-), underscore (_), period (.), and tilde (~). These characters have no structural meaning and require no escaping.
  • Reserved Characters (Syntactic Delimiters): :, /, ?, #, [, ], @, !, $, &, ', (, ), *, +, ,, ;, and =. These characters serve as delimiters between URI schemes, hosts, paths, queries, and fragments.

When you need to transmit data that happens to contain one of these reserved characters (for example, searching for "C++ & Python" in a query parameter), the character must be translated into its percent-encoded hexadecimal representation: a percent sign (%) followed by the two-digit hexadecimal code representing the byte in UTF-8. For example, a space becomes %20, an ampersand becomes %26, and a plus sign becomes %2B.

encodeURI vs. encodeURIComponent: The Critical Difference

One of the most persistent bugs in web applications stems from confusing JavaScript's two native encoding functions:

encodeURI(fullUrl)

Designed for encoding an entire complete URL address. It intentionally preserves :, /, ?, and & so the overall URL structure remains valid. 

// Preserves protocol and query delimiters:
encodeURI("https://api.com/v1/search?q=hello world");
// -> "https://api.com/v1/search?q=hello%20world"

encodeURIComponent(paramValue)

Designed for encoding an individual parameter value. It encodes all reserved characters (including &, =, and /) so user data cannot break the query string. 

// Encodes & and = into safe values:
encodeURIComponent("alpha&beta=gamma");
// -> "alpha%26beta%3Dgamma"

Why + vs %20 Matters in Query Strings

Developers frequently ask whether spaces should be encoded as %20 or +. The distinction is historical:

Under RFC 3986, the official percent-encoding for a space character is %20. However, the older HTML 4 / 5 Form specification for application/x-www-form-urlencoded payloads mapped spaces to the plus sign (+). In modern web services, passing %20 is always safe in both path segments and query strings, whereas + in a URL path is interpreted as a literal plus sign!
